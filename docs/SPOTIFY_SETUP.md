# Spotify Listening Activity — Setup

This integration renders three SVG cards from your Spotify listening history:

- `spotify-recent.svg` — five most recent tracks with album art
- `spotify-top-artists-24h.svg` — top 5 artists (rolling 24 hours)
- `spotify-top-artists-7d.svg` — top 5 artists (rolling 7 days)

They are regenerated by `.github/workflows/spotify.yaml` roughly every 15 minutes and embedded in the README between `<!--SPOTIFY:start-->` / `<!--SPOTIFY:end-->`.

## 1. Create a Spotify Developer application

1. Go to <https://developer.spotify.com/dashboard> and sign in.
2. Click **Create app**.
3. App name / description: anything you like (e.g. `github-profile-listening`).
4. **Website:** your GitHub profile URL (optional).
5. Accept the Developer Terms and create.
6. On the app page, note the **Client ID** and reveal the **Client Secret**.

## 2. Register the redirect URI

Spotify requires the redirect URI to match **exactly** between the Dashboard and the local helper script. Spotify also requires an explicit loopback IP (not `localhost`).

In the Dashboard, click **Edit Settings** and add:

```
http://127.0.0.1:8888/callback
```

Save.

## 3. Authorize the required scope and obtain a refresh token

The only scope requested is `user-read-recently-played`.

From this repository, run:

```bash
node scripts/spotify-auth.mjs
```

The script will:

1. Prompt for your Client ID and Client Secret (never stored to disk).
2. Start a local server on `http://127.0.0.1:8888/`.
3. Print a Spotify authorization URL — open it in your browser and approve.
4. Receive the redirect at `/callback`, exchange the code, and print your **refresh token once**.
5. Shut down the local server.

Copy the refresh token immediately; it is not saved.

## 4. Create GitHub Actions secrets

Repo → **Settings → Secrets and variables → Actions → New repository secret**. Create three:

| Name                    | Value                          |
| ----------------------- | ------------------------------ |
| `SPOTIFY_CLIENT_ID`     | your Spotify app Client ID     |
| `SPOTIFY_CLIENT_SECRET` | your Spotify app Client Secret |
| `SPOTIFY_REFRESH_TOKEN` | the value from step 3          |

Do **not** paste these into README, code, or a committed `.env`.

## 5. Enable workflow write permission

Repo → **Settings → Actions → General → Workflow permissions** → select **Read and write permissions**. This lets the workflow commit updated SVG cards back to `main`.

## 6. Run the workflow manually

Repo → **Actions** tab → **Spotify Listening Activity** → **Run workflow** → **Run**.

The first run will:

- Fetch the last ~50 played tracks from Spotify.
- Write `data/spotify-plays.json` (the local 7-day store).
- Generate the three SVG cards.
- Update the `<!--SPOTIFY:...-->` block in `README.md`.
- Commit only if any of those files actually changed.

## 7. Accumulation caveat for 24h / 7d rankings

Spotify's Web API does not expose per-day play counts. The 24-hour and 7-day artist rankings are computed by this integration from the `recently-played` endpoint (which returns ~50 recent items).

That means the rankings become **accurate only after the workflow has been running for at least 24 hours (or 7 days)**. Before that, they reflect only whatever plays have been collected since setup.

## 8. Manual run at any time

Same as step 6 — the workflow has `workflow_dispatch` enabled so you can trigger it whenever.

## 9. Disable or remove the integration

- **Pause:** disable the workflow in **Actions → Spotify Listening Activity → ⋯ → Disable workflow**.
- **Remove entirely:**
  - Delete `.github/workflows/spotify.yaml`, `scripts/spotify/`, `scripts/spotify-auth.mjs`, `data/spotify-plays.json`, and the three `spotify-*.svg` files.
  - Delete the `<!--SPOTIFY:start-->` / `<!--SPOTIFY:end-->` block in `README.md`.
  - Delete the three GitHub Actions secrets.
  - (Optional) revoke the app at <https://www.spotify.com/account/apps/>.

## Design notes

- **Artist counting:** every credited artist on a track gets +1 per play (deduped within a single track). Featured artists count the same as leads.
- **Dedupe key:** `${track_id}@${played_at}` — Spotify returns the same track multiple times if replayed at different timestamps, and each spin is counted.
- **Retention:** plays older than 7 days are pruned every run.
- **No client-side JS in README:** cards are static SVGs with base64-embedded images and CSS `@media (prefers-color-scheme: dark)` for theme switching.
- **Rate limiting:** the fetcher honors Spotify's `Retry-After` header on `429` responses.

## Troubleshooting

- **`Spotify authorization failed (refresh token invalid or expired)`** — refresh token was revoked. Re-run `scripts/spotify-auth.mjs`.
- **`Spotify rate limit exceeded`** — the workflow honors `Retry-After`; if this persists, lower cadence in the cron.
- **Cards render but images are placeholders** — Spotify image CDN returned non-200. Try re-running; missing images fall back to a music-note placeholder.
- **No commits happen** — expected when nothing has changed since the last run.
